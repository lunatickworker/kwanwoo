# P2P 암호화폐 관리 시스템 계층 구조 설계서 v1.1

## 📋 문서 개요
- **작성일**: 2025-11-28
- **버전**: 1.2 (최종 확정)
- **목적**: 기존 2단계 구조(Admin-User)를 5단계 계층 구조로 확장 설계
- **중심**: 센터(Lv2) 기반 설계

### 📝 변경 이력
- **v1.0**: 초기 작성 (5단계 계층 구조 설계)
- **v1.1**: 커미션 정산 프로세스 명확화 (숫자 계산 방식)
- **v1.2**: 전체 비즈니스 프로세스 명확화
  - 커미션 비율 설정/변경 권한 명확화
  - 에이전시 역할 명확화 (센터 영업 파트너)
  - 센터 코인 조달 방식 명확화 (외부 거래소 구매)
  - 회원-가맹점 간 코인 흐름 명확화 (블록체인 + 게임 포인트)
  - 가맹점 게임 플랫폼 독립 운영 명확화
  - 출금 프로세스 추가

---

## 💡 핵심 비즈니스 모델

### 간략 기능 요지

```
마스터(Lv0)
└─> 센터에게 코인 구매대행 솔루션 제공

센터(Lv2)
└─> 가맹점을 대신해서 코인 구매대행

가맹점(Lv3)
└─> 회원들이 구매한 코인으로 게임을 하는 곳 (게임 플랫폼)

회원(Lv4)
└─> 가맹점에서 게임을 위해 코인 구매
```

### 수익 구조

각 계층은 거래가 발생할 때마다 **커미션을 정산**받습니다:
- **가맹점**: 회원 구매 금액의 X% (예: 0.5%)
- **센터**: 회원 구매 금액의 Y% (예: 0.2%)
- **에이전시**: 회원 구매 금액의 Z% (예: 0.1%)

커미션은 **숫자로만 계산**되고, **정해진 정산일에 수동 지급** 후 시스템에 완료 표시합니다.

## 🎯 계층 구조 (Hierarchy)

```
마스터(Lv0) - 솔루션 제공자
    ↓ 관리
에이전시(Lv1) - 통계 모니터링
    ↓ 관리
센터(Lv2) ⭐ 핵심 운영 계층 - 코인 구매대행
    ↓ 관리
가맹점(Lv3) - 게임 플랫폼
    ↓ 서비스 제공
회원(Lv4) - 게임 사용자
```

## 🏗️ 계층별 역할 및 권한

### 🔴 마스터 (Lv0) - 최상위 관리자

**역할**: 전체 시스템 총괄 관리 및 파트너십 관리

**권한**:
- ✅ **파트너 생성 및 관리 (CRUD)**
  - 에이전시(Lv1) 생성/수정/삭제
  - 센터(Lv2) 생성/수정/삭제
  - **센터 생성 시 부모 에이전시 선택** (에이전시에서 자기 센터 관리 기능)
  - **커미션 비율 설정 및 변경**
    - 에이전시 생성 시 커미션 비율 입력 (예: 0.1%)
    - 센터 생성 시 커미션 비율 입력 (예: 0.2%)
    - 생성 후 마스터만 에이전시/센터 커미션 비율 변경 가능
    - 변경 시점부터 새로운 비율로 재계산
    - **가맹점 커미션은 센터가 자율 관리** (마스터 개입 없음)
  
- ✅ **가맹점 승인 관리**
  - 가맹점 가입 요청 최종 승인/거부
  - 가맹점 상태 관리 (활성/정지/차단)
  
- ✅ **센터 및 가맹점 매출 관리**
  - 전체 매출 대시보드
  - 센터별/가맹점별 매출 통계
  - 실시간 거래 모니터링
  
- ✅ **도메인 관리**
  - 센터별로 여러 도메인 연결
  - 도메인 활성/차단 관리
  
- ✅ **하부 조직 커미션 정산 관리**
  - 에이전시 커미션 정산
  - 센터 커미션 정산
  - 정산 요청 검증 및 승인 표시
  - 정산 히스토리 조회

**화면 구성**:
- 대시보드 (전체 시스템 통계)
- 파트너 관리 (에이전시/센터 + 커미션 설정)
- 가맹점 승인 관리
- 매출 관리
- 커미션 정산
- 도메인 관리

**제거된 기능**:
- ❌ 시스템 설정 및 보안 (센터로 이동)
- ❌ 전역 가스비 정책 설정 (센터로 이동)
- ❌ 보안 모니터링 (센터로 이동)
- ❌ 시스템 로그 조회 (센터로 이동)

---

### 🟠 에이전시 (Lv1) - 센터 영업 파트너 (통계 뷰어)

**역할**: 센터 모집 및 소속 센터들의 매출 모니터링

**비즈니스 모델**: 에이전시는 센터를 모집하고, 소속 센터들의 코인 구매 거래량에 대해 마스터가 설정한 커미션 비율로 정산을 받습니다.

**권한**:
- ✅ **센터 매출 관리 (뷰 전용)**
  - 소속 센터 목록 조회
  - 센터별 매출 통계
  - 센터별 입출금 관리 및 통합 입출금 관리
  - 실시간 거래 모니터링
  - 일자별 검색 통계 확인
  
- ✅ **본인 커미션 정산 관리**
  - 커미션 내역 조회 (숫자로만)
  - **정산 요청** (마스터에게 알림 → 마스터 검증 → 승인 표시)
  - 정산 히스토리
  
- ✅ **센터 현황 모니터링**
  - 센터별 회원 수
  - 센터별 거래량
  - 센터별 활성도

**화면 구성**:
- 대시보드 (소속 센터 통계)
- 센터 매출 관리
- 센터 입출금 관리 (통합 뷰)
- 커미션 정산

**제한 사항**:
- ❌ 센터 생성 불가 (마스터만 가능)
- ❌ 회원 직접 관리 불가
- ❌ 가맹점 승인 불가
- ❌ 커미션 자동 입금 없음 (숫자 계산만, 정산 시 수동 지급)

**중요**: 에이전시는 **뷰(View) 기능만** 제공하며, 하위 센터들의 모든 통계를 확인할 수 있습니다.

### 🟢 센터 (Lv2) - **핵심 운영 계층** ⭐

**역할**: 실질적인 코인 거래 및 회원/가맹점 관리 (코인 구매대행)

**비즈니스 모델**: 센터는 외부 거래소(업비트, 바이낸스 등)에서 코인을 구매하여 센터 Hot Wallet에 보관하고, 회원의 구매 요청 시 검증 후 회원 지갑으로 전송합니다. 거래량에 대해 마스터가 설정한 커미션 비율로 정산을 받습니다.

**권한**:

#### 1. 코인 관리
- ✅ **코인 조달 및 보관**
  - 외부 거래소에서 코인 구매 (업비트, 바이낸스 등)
  - 센터 Hot Wallet에 코인 보관
  - 코인 재고 관리
  
- ✅ **코인 구매 요청 처리 (계좌이체 방식)**
  - 회원의 구매 요청 승인/거절
  - 입금 확인 후 코인 지급 (센터 지갑 → 회원 지갑)
  
- ✅ **코인 판매 관리**
  - 판매 요청 처리
  - 계좌 출금 처리
  
- ✅ **코인 트랜잭션 관리**
  - 입금 내역 조회
  - 출금 내역 모니터링
  - 실시간 블록체인 동기화
  
- ✅ **코인 종류 관리**
  - **현재**: KRWQ, USDC(가스비)만 구현
  - **향후**: TRC20 네트워크 추가 계획
  - 코인 설정 (수수료, 최소액)
  - 외부 API 연동 (가격, 네트워크)
  
- ✅ **코인 스왑 관리**
  - 스왑 내역 조회
  - 스왑 수수료 설정

#### 2. 지갑 관리
- ✅ **회원 지갑 생성 관리**
  - 신규 회원 지갑 자동 생성
  - 지갑 주소 조회
  - 지갑 잔액 관리
  
- ✅ **가맹점 지갑 관리**
  - 가맹점 지갑 생성
  - 파트너 코드(가맹점 계정 아이디)와 지갑 매핑
  - 지갑 잔액 관리

#### 3. 회원 관리
- ✅ **회원 생성 및 관리 (CRUD)**
  - 회원 가입 기능
  - 관리자 페이지에서 회원 추가 기능
  - 회원 목록 조회
  - 회원 정보 수정
  - 회원 등급 관리 (Basic/Standard/Premium/VIP)
  - 회원 상태 관리 (활성/정지/차단)
  
- ✅ **계좌 인증 관리**
  - 1원 인증 요청 처리
  - 인증 승인/거절
  
- ✅ **실시간 고객 관리**
  - 고객센터 (1:1 채팅)
  - 문의 내역 관리
  - 실시간 알림

#### 4. 가맹점 관리
- ✅ **가맹점 생성 (CRUD)**
  - 가맹점 정보 등록
  - **가맹점 생성 시 커미션 비율 설정** (예: 0.5%)
  - 가맹점 지갑 생성
  - **파트너 코드**: 가맹점 계정(아이디)으로 대체
  
- ✅ **가맹점 커미션 비율 관리**
  - 센터가 자율적으로 설정 및 변경 가능
  - 마스터 승인 불필요 (등록 시에만 승인 필요)
  - 변경 시점부터 새로운 비율로 재계산
  
- ✅ **가맹점 코드 관리**
  - 추천인 코드 발급 (가맹점 아이디)
  - 코드별 매출 추적
  
- ✅ **가맹점 등록 승인 프로세스**
  - 센터에서 가맹점 생성
  - 마스터 승인 필요 (최초 등록 시만)
  - 승인 후 센터가 완전한 관리 권한 보유

#### 5. 가스비 정책 관리
- ✅ **회원 등급별 가스비 정책 설정**
  - VIP/Premium: 100% 운영자 부담
  - Standard: 부분 지원
  - Basic: 100% 사용자 부담
  
- ✅ **가스비 모니터링**

#### 6. 입출금 자동화 ⭐ **핵심 프로세스**

**중요**: 회원 구매 요청 → 센터 승인 → 자동 처리

```
1. 회원(Lv4) 구매 요청 (예: KRWQ 100만원)
   ↓
2. 센터(Lv2) 관리자가 입금 확인 후 승인
   ↓
3. 자동 처리:
   
   [A] 회원 지갑에 코인 입금 (TX1)
       - 구매 금액 전액을 회원 지갑에 입금
       - 예: 100만원 KRWQ
       - transactions 테이블에 기록
   
   [B] 가맹점 지갑으로 자동 전송 (TX2)
       - 회원 지갑에서 가맹점 지갑으로 100만원 KRWQ 전송 (블록체인)
       - 가맹점은 자체 게임 플랫폼에서 회원 게임계정에 포인트 충전
       - transactions 테이블에 기록
       - **커미션 계산** (commissions 테이블에 기록만)
       
       ⚠️ **중요**: 
       - 회원 지갑 잔액은 0원이 됨 (가맹점 지갑으로 전송 완료)
       - 가맹점은 받은 코인을 확인 후 자체 게임 플랫폼에서 회원에게 포인트 지급
       - 우리 시스템은 블록체인 코인 입출금만 담당 (게임은 가맹점 자체 운영)
   
   [C] 센터 커미션 계산
       - 커미션 비율 적용 (예: 거래액의 0.2% = 2,000원)
       - commissions 테이블에 기록만 ✅
       - **실제 코인 이동 없음** ✅
   
   [D] 에이전시 커미션 계산
       - 커미션 비율 적용 (예: 거래액의 0.1% = 1,000원)
       - commissions 테이블에 기록만 ✅
       - **실제 코인 이동 없음** ✅

4. 트랜잭션 Receipt 확인 및 기록
   - TX1: 센터 → 회원 지갑 (100만원)
   - TX2: 회원 지갑 → 가맹점 지갑 (100만원)

5. 회원 및 가맹점에게 알림 발송
```

**화면 구성**:
- 대시보드 (센터 통계)
- 사용자 및 지갑 관리
- 계좌 인증 관리
- 코인 구매 요청 관리
- 입출금 관리 (입금/출금 내역)
- 스왑 관리
- 가맹점 관리
- 코인 관리
- 가스비 정책 관리
- 고객센터
- 보안 모니터

**현재 구현 상태**: ✅ 대부분 구현 완료 (기존 Admin 페이지가 센터 역할)

**제거된 기능**:
- ❌ Biconomy 가스 스폰서십 설정 (간소화)

---

### 🟡 가맹점 (Lv3) - 게임 플랫폼

**역할**: 회원 유치 및 자체 게임 서비스 제공

**비즈니스 모델**: 
- 가맹점은 자체 게임 플랫폼(카지노, 베팅 사이트 등)을 운영합니다.
- 회원이 코인을 구매하면 가맹점 지갑으로 자동 전송되고, 가맹점은 자체 플랫폼에서 회원에게 게임 포인트를 지급합니다.
- 거래량에 대해 센터가 설정한 커미션 비율로 정산을 받습니다.
- **우리 시스템의 범위**: 블록체인 코인 입출금만 담당 (게임은 가맹점이 독립적으로 운영)

**권한**:
- ✅ **가맹점 지갑 관리**
  - 가맹점 지갑 조회 (회원들이 구매한 코인 보관)
  - 커미션 수익 확인 (숫자로만)
  - 코인 전송 기능 (자체 게임 사이트 출금 요청 시 회원 지갑으로 전송)
  
- ✅ **트랜잭션 조회**
  - 추천인 코드(가맹점 아이디)로 유입된 회원 거래 내역
  - 커미션 내역 (숫자로만)
  
- ✅ **코인 정산 요청**
  - 정산 가능 금액 조회
  - 정산 요청 (센터 검증 → 승인 표시)
  - 정산일에 수동 지급 → 시스템 완료 표시
  
- ✅ **가입 프로세스**

### 2. commissions 테이블 (신규) - 커미션 계산 기록용

```sql
CREATE TABLE commissions (
  commission_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  
  -- 커미션 대상
  recipient_id UUID REFERENCES users(user_id), -- 커미션 받는 사람 (에이전시/센터/가맹점)
  recipient_level INTEGER, -- 1: 에이전시, 2: 센터, 3: 가맹점
  
  -- 거래 정보
  transaction_id UUID REFERENCES transactions(transaction_id),
  user_id UUID REFERENCES users(user_id), -- 거래한 회원
  
  -- 커미션 금액 (숫자 계산용)
  transaction_amount DECIMAL(20,8), -- 원본 거래 금액
  commission_rate DECIMAL(5,2), -- 적용 커미션 비율 (%)
  commission_amount DECIMAL(20,8), -- 커미션 금액 (숫자로만)
  coin_type TEXT, -- 코인 종류
  
  -- 상태
  status TEXT DEFAULT 'pending', -- 'pending' | 'settled' | 'paid' | 'cancelled'
  
  -- 정산 정보
  settlement_id UUID, -- 정산 배치 ID
  paid_at TIMESTAMP, -- 수동 지급 완료 시각
  
  -- 기타
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

-- 중요: 이 테이블은 커미션 "계산" 기록용입니다.
-- 실제 코인 자동 이동은 없으며, 정산 시 수동 지급합니다.
```

## 🔄 자동 코인 전송 프로세스 (핵심!)

### 회원 구매 요청 승인 시 자동 처리 흐름

```
1. 회원(Lv4) 구매 요청
   예: KRWQ 100만원 구매
   ↓
   
2. 센터(Lv2) 관리자가 입금 확인 후 승인
   ↓
   
3. 자동 처리 시작:
   
   [A] 회원 지갑에 코인 입금 (TX1)
       - 구매 금액 전액을 회원 지갑에 입금
       - 센터 Hot Wallet → 회원 지갑
       - 금액: 100만원 KRWQ
       - transactions 테이블에 기록
       - TxHash: 0xabc123...
   
   [B] 가맹점 지갑으로 자동 전송 (TX2)
       - 회원 지갑 → 가맹점 지갑
       - 금액: 100만원 KRWQ (전액)
       - referral_code로 가맹점(Lv3) 찾기
       - transactions 테이블에 기록
       - TxHash: 0xdef456...
       
       + 가맹점 커미션 계산
         - 가맹점 커미션 비율 적용 (예: 0.5% = 5,000원)
         - commissions 테이블에 기록 (숫자만)
         - 실제 코인 이동 없음!
   
   [C] 센터 커미션 계산
       - 센터 커미션 비율 적용 (예: 0.2% = 2,000원)
       - commissions 테이블에 기록 (숫자만)
       - 실제 코인 이동 없음!
   
   [D] 에이전시 커미션 계산
       - 에이전시 커미션 비율 적용 (예: 0.1% = 1,000원)
       - commissions 테이블에 기록 (숫자만)
       - 실제 코인 이동 없음!

4. 트랜잭션 Receipt 확인 및 기록
   - TX1: 센터 → 회원 지갑 (100만원 KRWQ)
   - TX2: 회원 지갑 → 가맹점 지갑 (100만원 KRWQ)
   
5. 회원 및 가맹점에게 알림 발송
   - 회원: "코인 입금 완료 (가맹점으로 전송됨)"
   - 가맹점: "회원 ○○○님이 100만원 충전 - 게임 포인트 지급 필요"
   
6. 가맹점 처리
   - 가맹점이 가맹점 지갑에 100만원 KRWQ 입금 확인
   - 자체 게임 플랫폼에서 회원 계정에 100만원 포인트 지급
   - 회원은 가맹점 게임 플랫폼에서 게임 이용
```

### 예시

```
회원 홍길동이 KRWQ 100만원 구매 요청
  ↓
센터 관리자가 승인
  ↓
자동 처리:

[코인 이동 - 블록체인]
  - 홍길동 지갑에 KRWQ 100만원 입금 (TX1) ✅
  - 가맹점(partner123) 지갑에 KRWQ 100만원 전송 (TX2) ✅
  
  블록체인 결과:
    홍길동 지갑: 0원 (가맹점으로 전송 완료)
    가맹점 지갑: 100만원
    
[가맹점 처리 - 게임 플랫폼]
  - 가맹점이 지갑 입금 확인 (100만원 KRWQ)
  - 가맹점 자체 게임 플랫폼에서 홍길동 계정에 100만원 포인트 지급
  - 홍길동은 가맹점 게임에서 플레이

[커미션 계산 - 숫자만]
  - 가맹점 커미션: 5,000원 (0.5%) → commissions 테이블 기록
  - 센터 커미션: 2,000원 (0.2%) → commissions 테이블 기록
  - 에이전시 커미션: 1,000원 (0.1%) → commissions 테이블 기록
  
  * 커미션은 숫자로만 계산되며, 실제 코인 이동 없음
  * 정산일에 수동 지급 → 시스템 완료 표시
  
트랜잭션 Hash 기록:
  - TX1: 0xabc123... (센터 → 회원)
  - TX2: 0xdef456... (회원 → 가맹점)
```

## 💰 커미션 정산 프로세스

### 정산 흐름

```
1. 커미션 누적
   - 거래 발생 시마다 commissions 테이블에 기록 (숫자만)
   - 실제 코인 이동 없음
   - 상태: 'pending'

2. 정산 요청
   - 에이전시/센터/가맹점이 정산 요청
   - 정산 기간 선택 (예: 2025-11-01 ~ 2025-11-30)
   - settlements 테이블에 기록
   - 상태: 'pending'
   - 상위 계층에 알림

3. 검증 및 승인 표시
   - 마스터(에이전시/센터 정산) 또는 센터(가맹점 정산)가 검증
   - 정산 금액 확인
   - 시스템에 승인 표시
   - 상태: 'approved'

4. 수동 지급
   - 정해진 정산일에 관리자가 수동으로 지급
   - 이체/송금 등 수동 처리
   - 시스템에 지급 완료 표시
   - 상태: 'paid'
   - commissions 테이블의 관련 기록도 'paid'로 변경

5. 완료
   - 정산 완료
```

### 예시

```
가맹점 "Partner123"의 11월 커미션 정산:

1. 누적 커미션 (commissions 테이블)
   - 2025-11-01: 5,000원 (회원 홍길동 구매)
   - 2025-11-05: 3,000원 (회원 김철수 구매)
   - 2025-11-15: 7,000원 (회원 이영희 구매)
   - 총: 15,000원

2. 정산 요청 (2025-12-01)
   - 가맹점이 "11월 정산 요청" 클릭
   - 정산 금액: 15,000원 KRWQ
   - 센터에 알림

3. 센터 검증 및 승인 표시
   - 센터 관리자가 확인
   - 정산 내역 검증
   - 시스템에 "승인" 표시

4. 수동 지급 (2025-12-05, 정산일)
   - 센터 관리자가 가맹점 계좌로 15,000원 송금
   - 시스템에 "지급 완료" 표시

5. 완료
   - 가맹점 대시보드에 "지급 완료" 표시
```

## 🎯 센터(Lv2) 중심 설계 핵심 포인트

### 1. 센터가 핵심 운영 계층인 이유
- ✅ 실질적인 코인 거래 처리 (구매/판매/스왑)

- ✅ 회원 및 가맹점 직접 관리
- ✅ 가스비 정책 설정 및 관리
- ✅ 고객 지원 (실시간 문의)
- ✅ 자동 코인 전송 실행 (회원 → 가맹점)
- ✅ 자동 커미션 계산 실행

### 2. 센터의 자율성
- 센터별로 독립적인 회원/가맹점 관리
- 센터별로 맞춤형 가스비 정책 설정 가능
- **가맹점 커미션 비율을 자율적으로 설정 및 변경 가능**
  - 가맹점 생성 시 커미션 비율 입력 (예: 0.5%)
  - 생성 후 센터만 변경 가능 (마스터 승인 불필요)
  - 변경 시점부터 새로운 비율로 재계산
- 센터 자신의 커미션 비율은 마스터만 변경 가능

### 3. 센터의 책임
- 회원 자산 안전 관리
- 신속한 고객 지원
- 정확한 커미션 계산
- 가맹점 활동 모니터링
- 정확한 코인 전송 처리

### 4. 마스터의 역할
- 센터 생성 및 관리
- 센터 성과 모니터링
- 정산 검증 및 승인 표시
- **에이전시 및 센터 커미션 비율 설정 및 변경**
  - 에이전시/센터 생성 시 커미션 비율 입력
  - 생성 후에도 마스터만 변경 가능 (변경 시점부터 재계산)
  - 가맹점 커미션은 센터가 자율 관리 (마스터 개입 없음)

## 🔒 보안 및 권한 관리

### 계층별 접근 제한

```typescript
// 예시: 센터는 자신의 하위 계층만 관리 가능
const canManageUser = (managerId: string, targetUserId: string) => {
  const manager = getUserById(managerId);
  const target = getUserById(targetUserId);
  
  if (manager.hierarchy_level === 0) {
    // 마스터는 모든 사용자 관리 가능
    return true;
  }
  
  if (manager.hierarchy_level === 1) {
    // 에이전시는 뷰만 가능 (관리 불가)
    return false;
  }
  
  if (manager.hierarchy_level === 2) {
    // 센터는 소속 가맹점 및 회원만 관리 가능
    return target.center_id === managerId;
  }
  
  return false;
};
```

### 데이터 격리

```sql
-- 센터 관리자가 회원 목록 조회 시
SELECT * FROM users 
WHERE center_id = :center_id 
AND hierarchy_level >= 3;

-- 에이전시 관리자가 센터 목록 조회 시 (뷰 전용)
SELECT * FROM users 
WHERE agency_id = :agency_id 
AND hierarchy_level = 2;
```
