# 에이전시 관리 가이드

## 개요
마스터 대시보드에서 에이전시를 생성, 수정, 삭제하는 방법과 문제 해결 방법을 설명합니다.

## 에이전시 생성

### 필수 정보
- **에이전시명** (필수): 에이전시의 이름
- **이메일** (필수): 로그인에 사용되는 이메일 주소
- **비밀번호** (필수): 최소 8자 이상
- **연락처** (선택): 전화번호
- **담당자** (선택): 담당자 이름
- **사업자 번호** (선택): 사업자 등록번호
- **주소** (선택): 사업장 주소

### 생성 프로세스
1. "에이전시 생성" 버튼 클릭
2. 필수 정보 입력
3. "에이전시 생성" 버튼 클릭
4. Auth 사용자 자동 생성 (Supabase Auth)
5. Users 테이블에 에이전시 정보 저장
6. 생성 완료 메시지 표시

### 주의사항

#### 이메일 주소
- **실제 도메인을 사용해야 합니다** (예: @gmail.com, @naver.com, @company.com)
- test@test.com, admin@example.com 같은 테스트 이메일은 Supabase Auth에서 거부될 수 있습니다
- 이미 사용 중인 이메일은 사용할 수 없습니다

#### 비밀번호
- 최소 8자 이상
- 영문, 숫자, 특수문자 조합 권장
- 비밀번호와 비밀번호 확인이 일치해야 합니다

## 에이전시 수정

### 수정 가능한 정보
- 에이전시명
- 이메일 (로그인 계정이 변경됨)
- 연락처
- 담당자
- 사업자 번호
- 주소

### 수정 프로세스
1. 에이전시 카드에서 "수정" 버튼 클릭
2. 수정할 정보 입력
3. "수정 완료" 버튼 클릭
4. Users 테이블 업데이트
5. 수정 완료 메시지 표시

### 주의사항
- 이메일 변경 시 해당 계정으로 다시 로그인해야 합니다
- 비밀번호는 여기서 변경할 수 없습니다 (별도 비밀번호 재설정 기능 사용)

## 에이전시 삭제

### 삭제 프로세스
1. 에이전시 카드에서 휴지통 아이콘 클릭
2. 확인 메시지 확인
3. 삭제 확인
4. Auth 사용자 및 Users 테이블에서 삭제
5. 삭제 완료 메시지 표시

### 주의사항
⚠️ **삭제 시 주의사항**
- 삭제된 에이전시는 복구할 수 없습니다
- 하위 센터와 가맹점도 함께 삭제됩니다
- 모든 연관 데이터가 삭제됩니다

## 에이전시 활성화/비활성화

### 상태 변경
- 활성/비활성 토글 버튼 클릭
- 비활성화된 에이전시는 로그인할 수 없습니다
- 하위 센터와 가맹점의 접근도 제한됩니다

## 문제 해결

### 에이전시 생성 실패

#### 1. "이미 존재하는 이메일입니다"
**원인**: 해당 이메일이 이미 사용 중
**해결**: 다른 이메일 주소를 사용하세요

#### 2. "유효하지 않은 이메일 형식입니다"
**원인**: 실제 도메인이 아닌 테스트 이메일 사용
**해결**: 
- @gmail.com, @naver.com, @company.com 등 실제 도메인 사용
- 또는 Supabase 설정에서 이메일 확인 비활성화

#### 3. "이메일 전송 제한에 도달했습니다"
**원인**: Supabase 이메일 전송 제한 (시간당 제한)
**해결**: 잠시 후 다시 시도하거나 다른 이메일 사용

#### 4. "Auth 사용자가 생성되었지만 Users 테이블 삽입 실패"
**원인**: Auth 사용자는 생성되었지만 Users 테이블 삽입 실패
**해결**: 
1. Supabase Dashboard → Authentication → Users에서 해당 사용자 확인
2. 수동으로 사용자 삭제
3. 다시 시도

### Supabase 설정 확인

#### 이메일 확인 비활성화 (개발 환경)
1. Supabase Dashboard 로그인
2. Settings → Authentication
3. "Enable email confirmations" 비활성화
4. "Save" 클릭

#### RLS (Row Level Security) 확인
Users 테이블의 RLS가 비활성화되어 있어야 마스터가 모든 에이전시를 볼 수 있습니다.

```sql
-- RLS 비활성화 (이미 적용됨)
ALTER TABLE users DISABLE ROW LEVEL SECURITY;
```

## 통계 정보

각 에이전시 카드에는 다음 통계가 표시됩니다:
- **센터**: 해당 에이전시 하위의 센터 수
- **가맹점**: 해당 에이전시 하위의 가맹점 수
- **사용자**: 해당 에이전시 하위의 일반 사용자 수

통계는 페이지 로드 시 자동으로 계산되며, 실시간으로 업데이트됩니다.

## 권한 구조

```
Master (마스터)
  └── Agency (에이전시)
        ├── Center (센터)
        │     └── Store (가맹점)
        │           └── User (사용자)
        └── Store (가맹점)
              └── User (사용자)
```

- 에이전시는 하위 센터와 가맹점을 관리할 수 있습니다
- 에이전시는 센터를 생성하고 관리할 수 있습니다
- 에이전시는 가맹점을 생성하고 관리할 수 있습니다

## 베스트 프랙티스

1. **이메일 주소**: 항상 실제 도메인 사용
2. **비밀번호**: 강력한 비밀번호 사용 (최소 12자, 영문+숫자+특수문자)
3. **정보 입력**: 담당자 정보와 연락처를 입력하여 추후 관리 용이
4. **삭제 주의**: 삭제 전 하위 데이터 백업
5. **비활성화 활용**: 즉시 삭제보다는 비활성화로 임시 제한

## API 참고

### 에이전시 생성 API 흐름
```typescript
// 1. Supabase Auth 사용자 생성
const { data: authData } = await supabase.auth.signUp({
  email: formData.email,
  password: formData.password,
  options: {
    data: {
      role: 'agency',
      center_name: formData.agencyName,
    }
  }
});

// 2. Users 테이블에 정보 저장
const { error } = await supabase
  .from('users')
  .insert({
    user_id: authData.user.id,
    username: formData.agencyName,
    email: formData.email,
    role: 'agency',
    center_name: formData.agencyName,
    is_active: true,
    // ... 기타 정보
  });
```
